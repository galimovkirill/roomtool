## Аргумент

Если передан аргумент (например `TASK-002`) — выполни именно эту задачу.

Если аргумент не передан — определи следующую задачу автоматически:

```bash
grep -m1 "⬜" BACKLOG.md
```
Из вывода извлеки ID задачи (например `TASK-013`).

## Инструкция по выполнению задачи

1. Найди строку начала блока задачи:
   ```bash
   grep -n "### TASK-XXX" BACKLOG.md
   ```
   Используй номер строки как `offset` в инструменте Read, `limit: 80`.

2. Прочитай промпт задачи — он содержит точные требования.
3. Сверь с CLAUDE.md соглашения проекта (единицы, алиасы, стек).
4. Выполни все шаги из промпта строго по порядку.

## Проверка качества (обязательно после каждой задачи)

После выполнения всех шагов запускай проверки по порядку и исправляй все ошибки.

**Frontend** (если задача затрагивает `apps/frontend/`):
1. **Линтер:** `pnpm lint`
   - Ошибки → `pnpm lint:fix`, затем дочисти вручную
2. **Тайп-чек:** `pnpm exec tsc --noEmit`
3. **Тесты:** `pnpm test --run`
4. **Покрытие:** если изменён код в `store/`, `utils/`, `catalog/` — напиши или обнови тесты. Исключение: компоненты R3F (`scene/`) — Three.js не работает в jsdom, тестируй только вручную через Playwright. После написания прогони `pnpm test:coverage` и убедись, что пороги не упали.

**Backend** (если задача затрагивает `apps/backend/`):
1. **Линтер:** `cd apps/backend && go vet ./...`
2. **Тесты:** `cd apps/backend && go test ./...`

**OpenAPI** (если изменялся `apps/docs/openapi.yaml`):
- `make gen` — регенерировать оба типовых файла
- Убедись, что `git diff apps/backend/internal/api/types.gen.go` и `apps/frontend/src/api/types.gen.ts` содержат ожидаемые изменения

Только после прохождения всех проверок переходи к браузерной проверке.

## Браузерная проверка (для UI/visual задач)

**Пропусти** для задач с чисто логическими изменениями (store, utils, hooks, тесты, конфиги).

## Ревью (обязательно после проверки качества)

После прохождения lint/tsc/тестов — запусти `/review` через Skill tool (`skill: "review"`).

**Исправляй все замечания с оценкой ⚠️ и ❌.** После каждого исправления повторно запускай `pnpm lint && pnpm exec tsc --noEmit && pnpm test --run`.

Только косметические замечания, явно помеченные агентом как необязательные, можно пропустить.

## Синхронизация документации (Definition of Done)

Перед тем как сообщить о завершении — проверь, затронула ли задача что-либо из:

**Frontend → обновить `apps/frontend/CLAUDE.md`:**
- **Типы** (`apps/frontend/src/types/index.ts`) — новые/изменённые интерфейсы
- **Конфиги и константы** (`config/`, `catalog/`) — новые поля, категории, материалы
- **Store или utils** — новые мутации, алгоритмы, паттерны
- **Структура компонентов** — новые файлы в `components/`, переименования
- **Тесты** — новые паттерны или правила покрытия

**Backend → обновить `apps/backend/CLAUDE.md`:**
- **Новые handler'ы или маршруты** — структура запросов/ответов, бизнес-логика
- **Схема БД** — новые таблицы, колонки, индексы
- **Конвенции** — паттерны обработки ошибок, правила транзакций

**Корневой `CLAUDE.md`:**
- Изменение OpenAPI workflow, CI, команд монорепо

**Обновляй только «почему» и договорённости, не пересказывай код.**
Дерево файлов обновляй только при добавлении/удалении файлов, а не при переименовании функций.
