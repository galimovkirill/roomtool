## Аргумент

Если передан аргумент (например `TASK-002`) — выполни именно эту задачу.

Если аргумент не передан — определи следующую задачу автоматически:
```bash
grep -m1 "⬜" BACKLOG.md
```
Из вывода извлеки ID задачи (например `TASK-013`).

## Инструкция по выполнению задачи

1. Найди строку начала блока задачи:
   ```bash
   grep -n "### TASK-013" BACKLOG.md
   ```
   Используй номер строки как `offset` в инструменте Read, `limit: 80` — этого достаточно для любого блока задачи.

2. Прочитай промпт задачи — он содержит точные требования.
3. Сверь с CLAUDE.md соглашения проекта (единицы, алиасы, стек).
4. Выполни все шаги из промпта строго по порядку.

## Проверка качества (обязательно после каждой задачи)

После выполнения всех шагов задачи **всегда** запускай три проверки по порядку и исправляй все ошибки:

1. **Линтер:** `pnpm lint`
   - Если есть ошибки — исправь их в коде (или запусти `pnpm lint:fix` для автоисправления, затем добей вручную)
   - Повтори пока `pnpm lint` не завершится без ошибок

2. **Тайп-чек:** `pnpm exec tsc --noEmit`
   - Если есть ошибки типов — исправь их в коде
   - Повтори пока тайп-чек не завершится без ошибок

3. **Тесты:** `pnpm test --run`
   - Если тесты падают — исправь код или тесты
   - Повтори пока все тесты не проходят

Только после прохождения всех трёх проверок переходи к браузерной проверке.

## Браузерная проверка (обязательно для UI/visual задач)

Запусти `pnpm dev` и проверь через Playwright **если выполняется хотя бы одно условие:**
- промпт задачи содержит слово «браузер» или фразу «убедись» с описанием видимого результата
- задача создаёт или меняет компоненты в `scene/`, `panels/`, `ui/`
- задача затрагивает Canvas, Three.js, CSS-layout или визуальное поведение

**Что проверять:**
1. Страница открывается без ошибок в консоли
2. Ключевой визуальный результат задачи виден на экране (скриншот через Playwright)
3. Если что-то не отображается — диагностируй причину через `browser_evaluate`, не считай задачу выполненной

Задачи с чисто логическими изменениями (store, utils, hooks без UI, тесты, конфиги) — можно пропустить.

## Ревью (обязательно после проверки качества)

После того как lint, tsc и тесты прошли — запусти `/review` через Skill tool (`skill: "review"`).

Агент вернёт ревью с оценками по категориям (✅ / ⚠️ / ❌).

**Исправляй все замечания с оценкой ⚠️ и ❌.** Для каждого исправления:
1. Внеси правку в код
2. Повторно запусти `pnpm lint && pnpm exec tsc --noEmit && pnpm test --run` — убедись что ничего не сломалось
3. Если появились новые проблемы — исправь их тоже

Если замечания только косметические и агент явно пометил их как необязательные — можно пропустить.

После исправлений задача считается выполненной.
