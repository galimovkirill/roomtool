Проведи код-ревью изменений в проекте RoomTool прямо в этом контексте (без Agent tool).

**Стек:** React 18 + TypeScript (strict), Three.js + @react-three/fiber, Zustand, Tailwind CSS v4, Vitest.
**Соглашения:** 1 unit = 1 мм, размеры из `src/config/scene.ts`, импорты через `@/`.

**Шаг 1 — собери изменения** (параллельно, один message):
- `git diff HEAD` и `git status --short` — запусти оба инструмента одновременно
- Если `git diff HEAD` пустой — запусти `git diff HEAD~1`
- Для файлов с `??` в git status — прочитай содержимое через Read tool

**Шаг 2 — проведи ревью по категориям** (✅ / ⚠️ / ❌):
1. **Баги и опечатки** — логические ошибки, неверные условия, edge cases которые сломают поведение
2. **Типобезопасность** — strict TS, нет `any`, касты обоснованы
3. **Архитектура** — соответствие паттернам проекта, нет дублирования логики
4. **Соглашения** — единицы мм, размеры из scene.ts, импорты @/, структура файлов
5. **Race conditions** — useEffect cleanup, stale closures, подписки без отписки
6. **Мёртвый код** — неиспользуемые импорты, переменные, типы
7. **Читаемость** — понятные имена, комментарии только где нужны
8. **Тесты** — покрытие достаточное, тесты на поведение а не реализацию
9. **UX** — aria, keyboard nav, неочевидное поведение для пользователя

По каждой найденной проблеме: файл и строка, описание, конкретное предложение.

Итог: можно мержить / нужны правки / нельзя мержить.
