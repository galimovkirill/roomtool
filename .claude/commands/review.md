Проведи код-ревью изменений в проекте RoomTool прямо в этом контексте (без Agent tool).

**Frontend-стек:** React 19 + TypeScript (strict), Three.js + @react-three/fiber, Zustand, Tailwind CSS v4, Vitest.
**Backend-стек:** Go 1.24, PostgreSQL, oapi-codegen v2 (handlers из OpenAPI spec).
**Соглашения:** 1 unit = 1 мм, размеры из `apps/frontend/src/config/scene.ts`, TS-импорты через `@/`, API-контракт в `apps/docs/openapi.yaml`.

**Шаг 1 — собери изменения** (параллельно, один message):
- `git diff HEAD` и `git status --short` — запусти оба инструмента одновременно
- Если `git diff HEAD` пустой — запусти `git diff HEAD~1`
- Для файлов с `??` в git status — прочитай содержимое через Read tool

**Шаг 2 — проведи ревью по категориям** (✅ / ⚠️ / ❌):

**Общие (frontend + backend):**
1. **Баги и опечатки** — логические ошибки, неверные условия, edge cases которые сломают поведение
2. **Архитектура** — соответствие паттернам проекта, нет дублирования логики
3. **Мёртвый код** — неиспользуемые импорты, переменные, типы/функции
4. **Читаемость** — понятные имена, комментарии только где нужны
5. **Тесты** — покрытие достаточное, тесты на поведение а не реализацию

**Frontend-специфичные:**
6. **Типобезопасность** — strict TS, нет `any`, касты обоснованы
7. **Соглашения** — единицы мм, размеры из scene.ts, импорты @/, структура файлов
8. **Race conditions** — useEffect cleanup, stale closures, подписки без отписки
9. **UX** — aria, keyboard nav, неочевидное поведение для пользователя

**Backend-специфичные:**
10. **API-контракт** — handler соответствует схеме в `openapi.yaml`, не редактирует `types.gen.go` вручную
11. **SQL-безопасность** — нет конкатенации строк в запросах, используются параметризованные запросы
12. **Обработка ошибок** — ошибки БД и внешних вызовов обрабатываются, не проглатываются
13. **HTTP-коды** — статусы ответов соответствуют REST-конвенциям и spec

По каждой найденной проблеме: файл и строка, описание, конкретное предложение.
